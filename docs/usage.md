# Руководство пользователя

Подробное описание форм и поведения Outlook Autosave. Краткая инструкция — в [README](../README.md).

## Главная форма

Основная форма открывается кнопкой `Настройки` в группе `Outlook Autosave` на вкладке `Главная` и состоит из блока статуса, блока действий и блока настроек.

### Статус

Основная форма показывает текущий статус:

- версию;
- автора;
- включено ли автосохранение;
- количество активных правил сортировки;
- краткий список активных правил: номера и названия, а если название не задано - короткое описание условия;
- интервал автосохранения;
- период обработки писем;
- включено ли логирование автосохранения;
- состояние таймера;
- последний и следующий запуск;
- предупреждение, если обработка не завершена из-за лимита писем и продолжится по таймеру.

### Действия

| Кнопка | Назначение |
| --- | --- |
| `Обновить статус` | Перечитывает текущие настройки и обновляет текст в блоке статуса. Ничего не сохраняет и не запускает обработку писем. |
| `Сохранить выбранные` | Сразу сохраняет вложения из выделенных писем Outlook в папку из настроек выбранных писем. Правила автосохранения, логирование правил и служебный индекс для этого действия не применяются. |
| `Настройки выбранных` | Открывает отдельные настройки для кнопки `Сохранить выбранные`: папку по умолчанию, разрешенные расширения и исключенные расширения. На автосохранение по правилам эти настройки не влияют. |
| `Включить` / `Отключить` | Динамическая кнопка автосохранения. Если автосохранение выключено, кнопка показывает `Включить`; если включено - `Отключить`. При включении сразу выполняется один запуск обработки и ставится следующий запуск по таймеру. |
| `Запустить` | Немедленно выполняет один запуск автосохранения по активным правилам за заданный период. Удобен для разовой загрузки старых вложений с большим периодом (см. [Какой период выбрать](#какой-период-выбрать)). Постоянный автоматический режим при этом не включается, если он был выключен. |

При ручном сохранении выбранных писем, если файл с таким именем уже существует в целевой папке, новое вложение сохраняется с числовым суффиксом, например `invoice (2).pdf`, а не пропускается.

Настройки выбранных писем работают отдельно от правил автосохранения:

- `Папка по умолчанию` — целевая папка для кнопки `Сохранить выбранные`;
- `Разрешенные расширения` — если заполнены, сохраняются только эти расширения;
- `Исключенные расширения` — если заполнены, эти расширения не сохраняются;
- если расширение есть и в разрешенных, и в исключенных, исключение имеет приоритет;
- если оба списка расширений пустые, сохраняются все вложения.

### Настройки

| Кнопка | Назначение |
| --- | --- |
| `Правила` | Открывает форму правил сортировки вложений. Здесь задаются условия отбора письма и вложения, исходная папка Outlook и целевая папка сохранения. |
| `Интервал` | Задает частоту автоматической проверки, например `30s`, `15m`, `12h`. Это только расписание запуска, а не глубина поиска писем. |
| `Период` | Задает, сколько последних дней (часов) каждая проверка пересматривает заново, например `24h`, `3d`, `7d`. Так ловятся письма, которые попали в папку с опозданием. На догрузку после простоя Outlook период не влияет: пропущенные письма обрабатываются все. Рекомендуется `1d`–`7d`; большие значения — только для разового `Запустить`. Период не может быть больше фактически доступного локального кеша Outlook. |
| `Логирование: Включить` / `Логирование: Отключить` | Включает или отключает запись файла `autosave.log` для автосохранения по правилам. По умолчанию логирование выключено. |

При включении автосохранения надстройка сразу проверяет письма за заданный период и начинает следить за исходными папками правил.
Изменение периода действует со следующей проверки; сбрасывать ничего не нужно.
Если автосохранение запустилось, но не нашло ни одной существующей исходной папки из активных правил, отметка последнего запуска не обновляется.
Если Outlook возвращает ошибку на отдельном письме или объекте внутри папки, надстройка пропускает этот элемент, пишет диагностическую строку через `Trace` (видна в DebugView) и продолжает обработку следующих писем.

## Правила сортировки

Правила определяют, из какой папки Outlook брать письма, какие вложения сохранять и в какую папку на диске.

### Поля правила

- `Название правила` — необязательное короткое имя для списка правил. На отбор писем и вложений не влияет.
- `Текст в имени файла` — необязательный фрагмент имени вложения.
- `Тема письма` — необязательный фрагмент темы письма.
- `Расширения` — необязательный список расширений через запятую, например `zip, pdf`.
- `Целевая папка` — абсолютная папка, куда сохранить вложение.
- `Исходная папка Outlook` — ограничение по папке письма.
- `Продолжить проверку следующих правил` — если включено, после этого правила вложение проверяется следующими правилами списка и может сохраниться еще в другие папки. По умолчанию выключено: проверка вложения заканчивается на этом правиле. Такое правило в списке помечается `[+ следующие правила]`.

Если `Название правила` заполнено, в верхнем списке показывается короткая строка вида `1. Оператор PDF`. Если название пустое, список показывает правило подробно по условиям.

Если `Тема письма` пустая, правило применяется к письмам с любой темой.

Если `Текст в имени файла` пустой, правило применяется ко всем вложениям указанного расширения из указанной исходной папки Outlook. У такого правила должны быть заполнены `Расширения`, `Целевая папка` и `Исходная папка Outlook`.

`Исходная папка Outlook` находит вложения только в пределах самой папки. Если в папке созданы дополнительные каталоги, то вложения глубже не будут найдены.

### Форма правил

Верхний список показывает сохраненные правила с порядковыми номерами. Галка `✓` в отдельной левой колонке означает, что правило активно; пустая левая колонка — что правило сохранено, но отключено. Синее выделение строк означает только текущий выбор правил. Можно выделять несколько правил через `Ctrl`/`Shift`, а `Ctrl+A` выделяет все правила. Чтобы включить или отключить выбранные правила, дважды щелкните по строке правила или используйте динамическую кнопку `Включить` / `Отключить`.

| Кнопка | Назначение |
| --- | --- |
| `Обзор` рядом с `Целевая папка` | Открывает выбор папки Windows и подставляет путь в поле `Целевая папка`. Это папка, куда будут сохраняться вложения по правилу. |
| `Выбрать` рядом с `Исходная папка Outlook` | Открывает форму выбора папки Outlook и подставляет выбранную папку как ограничение правила. |
| `Текущая` | Подставляет текущую открытую папку Outlook из активного окна Outlook в поле `Исходная папка Outlook`. Удобно, когда правило настраивается для папки, которая уже открыта. |
| `Добавить` | Добавляет новое правило из заполненных полей. Если правило с такими же условиями и той же целевой папкой уже есть, обновляет существующую строку и включает ее. Правило с теми же условиями, но другой целевой папкой добавляется как новое. |
| `Обновить` | Заменяет выбранное правило значениями из полей формы. Работает только когда выбрано одно правило. Активность правила, то есть наличие или отсутствие галки `✓`, сохраняется. Если новые условия и целевая папка совпадают с другим уже существующим правилом, форма покажет номер этого правила и его название, если оно задано. |
| `Удалить` | Запрашивает подтверждение и удаляет выбранные правила из списка формы. Для одного правила показывает его номер, для нескольких - количество выбранных правил. Окончательно изменение записывается только после нажатия `Сохранить`. После удаления оставшиеся правила перенумеровываются. |
| `Включить` / `Отключить` | Динамическая кнопка для выбранных правил. Если среди выбранных правил есть отключенные, кнопка показывает `Включить` и включает все выбранные. Если все выбранные правила активны - показывает `Отключить` и отключает все выбранные. |
| `Сохранить` | Сохраняет все правила, их активность и закрывает форму. Если в полях введено новое или измененное правило, оно сначала добавляется или обновляется, затем сохраняется весь список. |
| `Отмена` | Закрывает форму без сохранения изменений, сделанных после открытия формы. |

### Как сохраняются файлы

Автосохранение работает только через правила. Если вложение не подходит ни под одно активное правило, оно не сохраняется.

Правила проверяются сверху вниз. Вложение сохраняется по первому подходящему правилу; если у этого правила включено `Продолжить проверку следующих правил`, проверка идет дальше и вложение сохраняется также по следующим подходящим правилам, пока не встретится подходящее правило без этой отметки или не кончится список.

При автосохранении вложение сначала сохраняется с исходным именем файла, например `invoice.pdf`. После сохранения надстройка записывает служебную отметку в индекс обработанных вложений, чтобы повторный запуск или расширение периода не создавали дубль.

Если файл с таким именем уже есть и это не уже обработанное вложение из индекса, надстройка сохраняет новое вложение с датой письма в имени, например `invoice_2026-05-22_14-30-00.pdf`. Дата берется из времени получения письма, а не из даты создания файла на диске. Если датированное имя уже существует, повторный запуск или расширение периода не создают новую копию.

Чтобы повторные запуски и изменение периода обработки не плодили копии после обновления, автосохранение ведет служебный индекс обработанных вложений в целевой папке правила. Файл индекса называется `autosave.index`, создается автоматически и может быть скрытым. Его не нужно импортировать или редактировать вручную. Индекс и лог хранятся в UTF-8; файлы, оставшиеся от VBA-версии в ANSI, переводятся в UTF-8 автоматически.

При удалении файла из папки по настроенным правилам он не будет сохраняться повторно и создавать дубликаты.

## Логирование

Логирование включается глобально кнопкой `Логирование: Включить` / `Логирование: Отключить` на главной форме. Настройка сохраняется отдельно от автосохранения: можно включить автосохранение без логов или включить логи только на время проверки.

Если логирование включено, надстройка пишет файл `autosave.log` в целевую папку правила, по которому обрабатывается вложение. Для каждой целевой папки создается свой файл. Лог дописывается в конец и автоматически не очищается.

Каждая проверка пересматривает весь период, но уже обработанные вложения (записанные в `autosave.index`) в лог не пишутся, поэтому повторные проверки лог не раздувают. Но если при частых запусках регулярно находятся новые вложения, совпадения с уже существующими файлами или ошибки сохранения, лог может заметно разрастаться. Для постоянной работы можно держать логирование выключенным и включать его только на время проверки, либо периодически очищать старые файлы `autosave.log` вручную.

В строку лога записываются дата и время события, статус, причина, примененное правило, тема письма, дата письма, имя вложения и путь файла.

Поле правила пишется полностью: номер правила в списке, название правила, текст в имени файла, расширения, фильтр темы письма, исходная папка Outlook, целевая папка и отметка `Продолжить проверку следующих правил`. Пример фрагмента строки:

```text
RuleNo=3; RuleName="Все PDF"; FileText=""; Extensions="pdf"; Subject=""; SourceFolder="\\mailbox\Входящие"; Target="C:\Users\user\Downloads\test"; ContinueToNextRules=False
```

Возможные статусы:

- `Saved` — вложение сохранено;
- `SavedAsDatedCopy` — вложение сохранено с датой письма в имени, потому что исходное имя уже занято другим файлом;
- `SkippedExists` — вложение не записано в индекс, но и исходное имя, и имя с датой письма уже заняты файлами в целевой папке; вложение записывается в индекс и больше не проверяется;
- `FailedCreateFolder` — не удалось создать целевую папку;
- `SkippedNoTargetFolder` — целевая папка недоступна;
- `FailedSave` — ошибка при сохранении вложения.

Если для вложения не найдено подходящее правило, файловый лог не пишется, потому что у такого события нет целевой папки правила. Ошибки записи самого лога не должны останавливать автосохранение.

## Часто задаваемые вопросы

### Как работают интервал и период вместе?

Вложения сохраняются двумя способами, которые подстраховывают друг друга:

1. **Сразу, когда письмо появилось в исходной папке**: пришло, докачалось с сервера или его перенесли туда вручную либо правилом Outlook. Дата письма при этом не важна. Outlook может не сообщить о письмах, если их пришло много за раз (больше 16), — их подхватит проверка по таймеру.
2. **Проверкой по таймеру** раз в `Интервал`. Каждая проверка заново пересматривает письма за последний `Период`. Уже сохраненные вложения отсеиваются по `autosave.index`, поэтому дублей нет.

- `Интервал` — как часто запускать проверку. По умолчанию `12h`.
- `Период` — на сколько назад каждая проверка заглядывает заново, считая от момента проверки (по полю `Получено`). По умолчанию `24h`.

Кроме того, надстройка помнит время последней полной проверки каждой папки. Если Outlook был закрыт дольше периода, проверка начинается с этого времени, а не с начала периода, — так ничего не теряется после отпуска.

Значения задаются числом и единицей: `s` — секунды, `m` — минуты, `h` — часы, `d` — дни. Можно дробное число (`1.5h`), число без единицы считается секундами.

### Outlook был закрыт (отпуск, выходные). Сохранятся ли вложения из писем, пришедших за это время?

Да, все. Делать ничего не нужно.

После запуска Outlook вложения из докачанных писем начнут сохраняться сразу, а через 2 минуты проверка по таймеру пройдет по всем письмам с момента последней проверки перед закрытием — даже если отпуск длиннее периода.

Пример: Outlook закрыт 1 июля в 18:00, человек вернулся из отпуска 15 июля и открыл Outlook в 9:00. К 9:02 будут обработаны все письма с 1 июля 18:00. Если писем много, обработка пойдет порциями по 10 000 писем раз в минуту.

Условия:

- автосохранение было включено, когда Outlook закрывали;
- письма есть в локальном кеше Outlook (обычно хранится за 12 месяцев и больше).

Если Outlook догружал почту дольше обычного, письма, загруженные после проверки, сохранятся сразу при появлении в папке, а пропущенные — при следующих проверках в пределах `Периода`.

### От какого момента отсчитывается таймер?

Таймер не сохраняется между сеансами Outlook и отсчитывает `Интервал` заново:

- от запуска Outlook, если автосохранение включено: первый запуск — через 2 минуты (или через `Интервал`, если он короче), чтобы сразу обработать письма, пришедшие пока Outlook был закрыт;
- от нажатия `Включить` — сразу после первого прогона;
- от изменения `Интервала`;
- от нажатия `Запустить`, если автосохранение включено;
- от окончания предыдущего прогона.

Поэтому фактический шаг между запусками равен `Интервал` плюс длительность самого прогона. `Следующий запуск` в статусе — расчетное время на текущий сеанс Outlook.

Если в статусе `Автосохранение: Включено`, а `Таймер: Отключен`, откройте форму `Настройки` еще раз: при открытии надстройка восстанавливает таймер.

Интервал больше примерно 24 дней таймер Windows не поддерживает: фактическая проверка будет выполняться не реже чем раз в ~24,8 дня.

### Почему изменение периода не запускает проверку сразу?

Новый период действует со следующей проверки по таймеру. Чтобы проверить сразу, нажмите `Запустить`.

### Чем `Запустить` отличается от `Включить`?

Обе кнопки сразу проверяют письма за весь период. `Включить` дополнительно включает постоянный режим: проверки по таймеру и сохранение сразу при появлении письма в папке. `Запустить` работает разово и не включает автосохранение, если оно было выключено. При включенном автосохранении `Запустить` не прерывает догрузку писем после простоя Outlook.

Если первый прогон после `Включить` завершился ошибкой (например, не найдена ни одна исходная папка), автосохранение остается выключенным, а надстройка показывает причину.

### Насколько далеко назад можно искать письма?

Ограничений со стороны надстройки практически нет (`700d` допустимо), но Outlook отдает только письма из своего локального кеша. Если в режиме кеширования Exchange хранится почта за 12 месяцев, более старые письма не будут найдены. Подробнее — в [README](../README.md).

### Какой период выбрать?

Каждая проверка по таймеру пересматривает **все** письма за период. Чем больше период и чем короче интервал, тем больше работы у Outlook на каждой проверке. Проверка идет в основном потоке Outlook, и на это время он может подтормаживать.

Поэтому правило простое:

- **для постоянной работы — небольшой период**, `1d`–`7d`. Этого достаточно, чтобы поймать письма, которые попали в папку с опозданием. Простой Outlook (отпуск, выходные) от периода не зависит: пропущенные письма догружаются все;
- **глубокий период — только разово**, чтобы один раз загрузить старые вложения. После этого верните небольшой период.

Ориентир по нагрузке при 100 письмах в день в исходной папке:

| Период | Писем на каждой проверке | Нагрузка |
| --- | --- | --- |
| `1d` | ~100 | незаметно |
| `7d` | ~700 | незаметно |
| `30d` | ~3 000 | короткая пауза Outlook на каждой проверке |
| `365d` | ~36 500 | 4 порции по 10 000 писем на каждой проверке, Outlook заметно тормозит |

**Пример 1. Обычная работа.** `Интервал` = `15m`, `Период` = `3d`. Вложения сохраняются сразу при появлении письма; раз в 15 минут проверка пересматривает ~300 писем за 3 дня и подхватывает то, что могло проскочить.

**Пример 2. Разово загрузить вложения за два года.**

1. Настройте и сохраните правила.
2. Поставьте `Период` = `700d` и нажмите `Запустить`.
3. Дождитесь, пока в статусе пропадет строка «Обработка не завершена» (письма обрабатываются порциями по 10 000 раз в минуту; Outlook должен быть открыт).
4. Верните `Период` = `3d`.

Уже сохраненные вложения записаны в `autosave.index`, поэтому после возврата периода ничего не потеряется и не задублируется.

**Пример 3. Как не надо.** `Интервал` = `15m`, `Период` = `700d`. Каждые 15 минут надстройка будет заново перебирать все письма за два года — десятки тысяч писем порциями, — и Outlook будет постоянно подтормаживать. Новых вложений это не добавит: все уже сохранено после первого прохода.

Период меньше интервала (например, `Интервал` = `12h`, `Период` = `1h`) допустим: между проверками ничего не пропадет, потому что каждая проверка начинается не позже времени предыдущей. Просто перепроверка опоздавших писем будет короче.

### Письмо попало в папку позже — сохранится ли вложение?

Да. Когда письмо появляется в исходной папке — докачалось с сервера, его перенесли вручную или правилом Outlook, — надстройка сохраняет вложения сразу, независимо от даты письма.

Если Outlook не сообщил о письме (так бывает при массовой загрузке или переносе больше 16 писем за раз), его подхватит ближайшая проверка по таймеру, но только если оно не старше `Периода`. Для более старых писем нажмите `Запустить` с нужным периодом или выделите письма и нажмите `Сохранить выбранные`.

### Вложение уже сохранялось, я удалил файл. Как сохранить его снова?

Автоматически — никак: вложение записано в `autosave.index` и повторно не выгружается. Варианты:

- выделите письмо и нажмите `Сохранить выбранные` — файл сохранится в папку из настроек выбранных писем;
- удалите строку этого вложения из скрытого файла `autosave.index` в целевой папке (или весь файл) и нажмите `Запустить`. Без индекса уже существующие файлы не перезапишутся: при совпадении имени будет создана копия с датой письма или вложение будет пропущено, если такая копия уже есть.

### Целевая папка была недоступна (сетевой диск, флешка). Догрузятся ли вложения?

Да, если папка вернется в пределах `Периода`. Такие вложения не записываются в индекс (в логе `FailedCreateFolder` или `SkippedNoTargetFolder`), поэтому следующая проверка по таймеру попробует сохранить их снова. Если папка была недоступна дольше периода, после ее возвращения нажмите `Запустить` с периодом, который покрывает время недоступности.

### Я поменял целевую папку в правиле. Что будет?

Индекс ведется отдельно для каждой целевой папки. В новой папке индекса нет, поэтому ближайшая проверка сохранит в нее вложения за последний `Период`, а дальше — все новые. Чтобы перенести вложения за больший срок, нажмите `Запустить` с нужным периодом. Старая папка и ее файлы не трогаются.

### Можно ли настроить несколько правил на одну и ту же папку Outlook?

Да. На одну исходную папку можно повесить сколько угодно правил: папка все равно проверяется один раз за прогон, а каждое вложение сверяется со списком правил сверху вниз. Вложения одного письма могут разойтись по разным папкам: например, `.pdf` по одному правилу, `.zip` по другому.

### Если вложение подходит под несколько правил?

Это решает отметка `Продолжить проверку следующих правил` у правила:

- **выключена** (по умолчанию) — вложение сохраняется по этому правилу, следующие правила для него уже не проверяются;
- **включена** — вложение сохраняется по этому правилу, и проверка идет дальше по списку; оно сохранится и по следующим подходящим правилам, пока не встретится подходящее правило без отметки.

Так можно настроить оба сценария.

**Отчеты — и в свою папку, и в общую папку PDF:**

| № | Условие | Целевая папка | Продолжить |
| --- | --- | --- | --- |
| 1 | `pdf`, тема `Отчет` | `D:\Отчеты` | да |
| 2 | `pdf` | `D:\PDF` | нет |

Отчет сохранится в обе папки, остальные PDF — только в `D:\PDF`.

**Отчеты — только в свою папку, остальные PDF — в общую:** то же самое, но у правила 1 отметка выключена. Правило 2 тогда работает как «все остальные PDF». Здесь важен порядок: если поставить правило `pdf` выше, оно перехватит все PDF, и правило для отчетов не сработает.

**Одни и те же файлы в две папки (например, локально и на сетевой диск):** два правила с одинаковыми условиями и разными целевыми папками, у первого отметка включена.

Если два подходящих правила ведут в одну и ту же целевую папку, файл сохраняется один раз: второе правило увидит запись в `autosave.index` и пропустит вложение.

Отключенные правила (без галки `✓`) в отборе не участвуют и цепочку не прерывают.

### Почему сохраняются картинки из подписей?

Картинки в теле письма (например, `image001.png` из подписи) Outlook тоже считает вложениями. Если правило сохраняет `png` или `jpg`, они попадут в целевую папку. Сузьте правило через `Текст в имени файла` или `Тема письма`.

### Какие письма обрабатываются?

Только обычные письма. Приглашения на встречи, отчеты о доставке и другие элементы пропускаются. Вложенное письмо (`.msg`) сохраняется целиком как файл, если под правило подходит его расширение; вложения внутри него не извлекаются.

Проверяется только сама исходная папка Outlook, без вложенных папок. Для подпапки нужно отдельное правило.

### Есть ли ограничение на количество писем за один прогон?

Да, за один прогон проверяется не более 10 000 писем по всем исходным папкам вместе. Лимит нужен, чтобы Outlook не подвисал надолго: проверка идет в основном потоке Outlook.

Если писем за период больше, обработка разбивается на порции:

1. Прогон останавливается на лимите и запоминает для папки время последнего обработанного письма.
2. Через минуту запускается продолжение: оно начинает с этого места, а не с начала периода.
3. Так повторяется, пока не будут обработаны все письма периода; после этого проверки снова идут по обычному `Интервалу`.

При большом периоде так будет на **каждой** проверке, поэтому для постоянной работы держите период небольшим (см. [Какой период выбрать](#какой-период-выбрать)).

Пока обработка не завершена, в статусе показывается предупреждение, а после `Включить` или `Запустить` надстройка сообщает, что обработка продолжится автоматически. Продолжение работает и после `Запустить` при выключенном автосохранении, и после перезапуска Outlook (если автосохранение включено). Outlook при этом должен быть открыт.

Пример: разовый `Запустить` с периодом `700d`, в папке 35 000 писем за этот период. Все письма будут обработаны за 4 порции примерно за 3–4 минуты плюс время самого сохранения.

Папки, которые отстали сильнее всего, обрабатываются первыми. Если одна исходная папка недоступна (например, отключен общий почтовый ящик), ее отметка не меняется, и когда папка вернется, пропущенные письма будут обработаны.

### Где хранятся настройки?

В реестре текущего пользователя Windows: `HKCU\Software\VB and VBA Program Settings\OutlookAttachmentSaver\Settings`. Настройки общие для всех профилей Outlook этого пользователя Windows и совпадают с настройками VBA-версии. Кроме них надстройка хранит там же служебные значения `AutoSaveFolderProgress` (время последней проверки по папкам) и `AutoSaveRunIncomplete` (обработка не завершена); VBA-версия их не использует.
